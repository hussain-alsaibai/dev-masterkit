## New Tools Discovered & Verified

- **Graphify-Labs/graphify** — 133,956 stars, +1,173 today, 362 contributors,
  2,498 PRs, Apache-2.0, PyPI `graphifyy` v0.9.95 (263 releases), 1,755,205
  downloads in 30 days (+8.0% vs prior 30 days). **This resolves the
  carry-forward from 2026-10-19 and 2026-10-22.**
  - **Architecture (read from `v8/ARCHITECTURE.md`, not the README):**
    `detect() -> extract() -> build() -> cluster() -> analyze.* ->
    report.generate() -> export.to_*`. Stages communicate through **plain
    dicts and NetworkX graphs**, not shared objects. `cluster(G)` does not
    mutate the graph. `analyze.py` is sibling functions, **no single
    `analyze()` entry point**. `export.py` is one function per format
    (`to_json`, `to_html`, `to_obsidian`, `to_svg`, `to_graphml`,
    `to_cypher`, `to_canvas`).
  - **Two patterns worth stealing verbatim:**
    1. **The doc is drift-proofed by a test.** "Signatures below are the real
       ones — `tests/test_architecture_doc.py` imports every symbol named
       here, so this table cannot drift from the code." That is exactly the
       2026-10-23 failure mode (35 of 90 guides had drifted). They solved it
       with a test; we solved it with an audit. **A test is cheaper than an
       audit and runs every time.**
    2. **Edge confidence is a typed enum, not a float:**
       `EXTRACTED | INFERRED | AMBIGUOUS`, plus a `relation` label
       (`calls|imports|uses`). A float would be a lie dressed as a number.
  - **Benchmark caveat:** `BENCHMARKS.md` is dated **2026-07-05** (3.5 months
    stale) and was produced by the project's *own* harness, with competitors
    run as adapters inside it. The "71.5x fewer tokens" and "recall@10 0.497"
    claims are **hypotheses to reproduce, not facts.** Single-harness,
    self-adjudicated.
  - **Verdict on the carry-forward: competitor, not a tool to add.** It
    duplicates context-bridge's mission. But it installs into OpenClaw
    natively (`graphify install --platform claw`) and is on PyPI with 1.75M
    monthly downloads — so it is also a **dependency candidate for our own
    repos**, with the risk that it shadows context-bridge inside our workspace.
  - **Two things graphify has that context-bridge lacks:** an export layer
    (JSON/HTML/Obsidian/SVG/GraphML/Cypher/Canvas plus a `--wiki` mode) and
    `graph_diff(G_old, G_new)` — a cross-run graph diff, which is directly a
    "what changed since the last session" primitive.
  - **Three things context-bridge still has:** fully local and deterministic
    (graphify needs a model for non-code semantics — Claude vision for PDFs,
    images, configs), genuinely sub-millisecond FTS5 queries (graphify walks
    a graph), and a plain MCP surface (graphify is primarily a skill).

## Key Events

### A green badge over zero tests, and a version number that lied

Nine repos were audited for two claim-vs-fact gaps today:

- **5 repos** shipped a `pyproject.toml` version that lagged the module's
  `__version__` (`snapdb`, `fast-cache`, `tiny-cli`, `tiny-config`,
  `tiny-log`). A lagging `pyproject.toml` means the **published artifact
  reports an older version than the code it ships**.
- **4 repos** ran CI against a hardcoded list naming only *some* test files.
  A CI job that names one test file **passes** while the rest of the suite
  never runs. The badge is green and the coverage is a fiction.
- **`tiny-mcp-observability` had no test file at all** and its CI ran
  `pytest tiny_mcp_observability.py` — 0 items collected, exit 5. **The badge
  was red for a reason that had nothing to do with the module.**
- **`tiny-agent-memory-v2`'s CI pointed at a test file that did not exist**,
  so the job errored on parse rather than on behaviour.

All fixed and verified by test run.

### The spec is a better test oracle than we are used to

`tiny-mcp-skel` vendors the upstream `schema/2026-07-28/schema.json` into
`tests/` and runs a dedicated conformance case in CI. The spec is the oracle
and the oracle is versioned, so a spec change becomes a **failing test** rather
than drift nobody notices.

This is the same lesson graphify taught yesterday from the other direction:
they protect their architecture doc with a test that imports every symbol the
doc names. **A test beats an audit because it runs on every commit, forever, for
free.** Yesterday we found 35 drifted guides with a manual audit; today we
prevented a whole class with a test.

### The validator flagged 204 of 204 files — and 44 of them were fine

The first pass of the schema check reported **every** workflow file in the
workspace as broken. The cause was YAML 1.1: a bare `on:` key parses as the
boolean `True`, and the schema wants the string `"on"`. After normalising that
one key: **0 real errors across our 44 files.**

This is worth recording because it nearly produced a second bad artifact. A
validator that fails on 100% of its input invites the response "the validator
is broken" — and then the check gets removed. **Normalise the parser quirk,
then prove the validator still rejects the known-bad form** (it does:
`continue_on_error` -> REJECTED, `continue-on-error` -> PASS).

## Key Lessons

- **A pipeline is an artifact with a schema, and it deserves the same
  validation as code.** One key typo removed six repos' CI from existence.
  Nobody noticed because the badge was red — but for a reason that pointed at
  YAML, and the obvious response to a red badge is to blame the code.
- **A validator that fails on everything is a liability.** The YAML `on:`
  quirk flagged 204 of 204 files. The fix was to correct the parser
  normalisation, **not** to relax the check. Always prove a validator still
  rejects the known-bad form before trusting a clean result.
- **A parse failure must never be fixed by changing the test.** The file was
  never parsed, so the test was never run, so it cannot have failed.
  "Fixing" it that way converts a loud failure into a silent coverage gap —
  the exact failure mode this catalogue spent 2026-10-22 and 2026-10-23
  documenting.
