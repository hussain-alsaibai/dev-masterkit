## 1. The gate quoted the wrong sentence

`gh api repos/Kc1t/alethe-agents/issues/39/comments --paginate` (6 comments),
fed to the extracted `commentsResolved()`:

```
before -> "mapsiva: Hi Guys, tests matter for keeping software quality in check,
           whether that's unit tests, integration tests, or anything else in between."
```

That is the comment's **first line**. The claim that fired is two paragraphs
later:

```
Looking at the repo now, the `tests/` directory this issue points to
doesn't exist anymore.
```

A verdict that quotes the right answer and the wrong evidence is worse than a
wrong boolean: the boolean gets fixed when it misfires, the quote gets believed.

**Fixed:** the returned evidence is now the sentence that actually matched
(`sentences.findIndex(isAffirmative)`), not `body.split('\n')[0]`.

## 2. A hedge two sentences later was invisible

The same live comment continues:

```
If that already covers what this issue was asking for, happy to help close it out.
```

`assertsFix` tested only the matched sentence, so the conditional never reached
it. The fix widens the hedge window to the **next two sentences** — the claim
sits first, the hedge arrives after it, and a same-sentence test cannot see it.

Red-then-green on the exact body: **before**, that comment rejected the issue as
resolved; **after**, it does not — while HumbertoCG18's unhedged
`This looks resolved on 'main'.` still does.

## 3. "already working on it" read as "already resolved"

comment says the opposite of resolved — someone is about to open the PR. Fixed
by anchoring the pattern to a completion verb.
