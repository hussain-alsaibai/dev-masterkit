## 1. A syntax check is not an import check

`compile()` and `ast.parse` stop at the grammar. They do not execute an
annotated assignment; `import` on 3.8 does:

```python
X: dict[str, int] = {}
```

- **3.9+**: legal, no error. The subscription exists.
- **3.8**: `TypeError: 'type' object is not subscriptable` — raised at import,
  before any function in the module can run.
- **`ast.parse(src, feature_version=(3,8))`**: passes. It always passed.

So a CI job that "checks 3.8 compatibility" by parsing the file is measuring
the Python **grammar** and reporting it as the Python **runtime**.

## 2. The future import is part of the annotation

`from __future__ import annotations` (PEP 563) stores every annotation as a
string. With it, the module-level annotation above is **not evaluated on any
version**, and the same spelling is safe. Without it, the annotation is an
ordinary expression evaluated at import.

Proven here, both arms, Python 3.11.2 (`tools/probing-annotation-deferral.md`):

```
no future import     -> rc=1 NameError: name 'NOEXIST' is not defined
WITH future import   -> rc=0
```

The probe uses an **unresolvable name** rather than `dict[str, int]`, because
`dict[str, int]` is a valid expression on the interpreter running the probe and
would pass in both arms.

## 3. Census of our own libraries

Every `tiny-*` module was scanned for a module-level uppercase annotated
assignment using PEP 585/604 syntax, then each hit was checked for the future
import:

| library | declares | future import | verdict |
|---|---|---|---|
| `tiny-cli-table` | `>=3.7` (README badge and `pyproject.toml` agree) | **no** | `_STYLES: dict[str, dict[str, str]]` — import failure below 3.9 |
| `tiny-secret-mask` | `>=3.8` | yes (`tiny_secret_mask.py:42`) | deferred — fine |
| `tiny-llm` | `>=3.9` | yes | fine — deferred, and 3.9 allows the spelling anyway |
| `tiny-mcp-server` | `>=3.8` | yes, and the annotation is `Dict[...]` | fine twice over |
| `tiny-llm-budget`, `tiny-log`, `tiny-rate-limiter`, `tiny-router` | `>=3.8` each | yes | annotations are `typing`-based (`Any`, `FailMode`, `float`) |

`tiny-cli-table` is the one real defect: `requires-python = ">=3.7"` with a
3.9-only module-level constant and no future import. Recorded here, **not
repaired in this sync** — the repo is not in this sync's scope, and shipping a
fix means a patch release plus a 3.7 matrix row to prove it.

`tiny-llm-budget`, `tiny-log`, `tiny-rate-limiter` and `tiny-router` were
reported as hits by the first pass and are **not** defects; the first pass
matched every annotated constant, not just PEP 585 ones. The narrowing is the
same lesson as `tiny-skill-scan`'s first draft: the first report measures the
corpus, not the defect.
