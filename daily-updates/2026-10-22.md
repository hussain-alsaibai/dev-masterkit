## New Tools Discovered & Verified

- **`tiny-validator` v0.6.0** — fixed a real data-loss bug.
  `to_json_schema()` recovered field constraints by *parsing its own validator
  error message strings*. That shipped consequences in both directions:
  `choices` and `pattern` were silently dropped (so OpenAPI and MCP consumers
  saw unconstrained fields), AND arbitrary validator prose containing
  `'must be at least 999 characters of prose'` invented a `minLength` that was

## Key Events

### A bounty criterion that was never met, and never visible

`arakoodev/EdgeChains` #290 asks for an AWS Comprehend redaction utility and
for test cases. The test file existed. It was written against jest. The
project's `test` script runs vitest. So the runner loaded the file, found no
registered tests, and exited 0.

The bounty criterion 'add testcases' was unmet, and the repo looked complete.
This is the same shape as the 2026-10-21 finding — route redaction that had
never run in any install — from the opposite direction: there, a control was
silently inert; here, the *evidence* for the control was silently absent. Both
hide behind a green exit code.

### The bounty scanner scored the scam repos 2nd, 3rd, and 4th

Worth recording because `skills/bounty-scanner` still has the gap AGENTS.md
flagged. Today's #1 pick (`arakoodev/EdgeChains`) was real: 429 stars, 253
forks, created 2023. But the scanner flagged it `no_stars` (wrong — the star
lookup is unauthenticated and throttled) and reported `competing_prs=0` when
5+ real PRs already referenced #290, which is 25 unearned points on the top
pick.

Meanwhile ranks 2-4 were `Kristywvs22/gin`, `RoseMark45/echo`, and
`Tylerx3udv/go-github` — all created 2026-07, zero pushes after creation, not
forks, zero stars. Textbook fake mirrors planted to farm Opire bounties, and
they all cleared the star gate because the gate reads zero.

The fix is a **min-stars and min-age gate enforced before scoring**, plus a
star-lookup path that fails closed rather than defaulting to 0. A scorer that
cannot read a signal must not award points for its absence. Verified top pick
by hand instead: all 348 issues scanned, 168 filtered, 10 rejected as scam,
and the winner confirmed against `api.github.com` directly.

### `write({append: true})` overwrote two files

OpenClaw code mode's `write` tool replaces the file even when asked to append,
reports `changed: true`, and raises nothing. Cost ~20 tool calls and the loss
of a 950-line module and a 494-line test suite, twice. The `edit` tool has a
milder version of the same problem: it reported `firstChangedLine: 84` against
an anchor that did not match the file on disk, and still reported success.

Both are now a prompt (`prompts/safe-file-write-append.md`) because the lesson
is not specific to one tool — it is that a tool reporting success is claiming it
did what you asked, not that the result is what you meant.
