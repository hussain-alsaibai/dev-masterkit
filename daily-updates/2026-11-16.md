## 1. `gortex` #1418 — two more P2s, both about the shape of a predicate

The PR has now been through four review rounds. Two of them found defects

### P2-6 — `Intents` is a projection of rows, not a set of kinds

The guard that decides "is this checkout unattributed?" was written as a count:

```go
kinds := overview.IntentKinds()
if len(kinds) != 1 { return }        // "not exactly one kind"
if kinds[0] == "manual_config" { warn() }
```

Verified against the source before changing anything:

- `internal/indexer/checkout_overview.go:338-350` appends
  `string(intent.SourceKind)` **once per row** from `ListTrackingIntents`
- `internal/graph/store_sqlite/catalog.go:1149-1155` upserts on
  `ON CONFLICT(checkout_id, source_kind, source_locator)`

One checkout can hold two live rows of the same kind under different locators —
an old root and a new one. That yields `["manual_config", "manual_config"]`,
which is still fully unattributed, and `len(kinds) != 1` **suppressed the
warning**. A checkout with nothing recording its provenance reported clean.

**Fix:** `isManualConfigOnly` — non-empty list, every element `manual_config`.
Duplicates allowed; every attributed kind still disqualifies.

**Proof:** new predicate vs old over nine intent sets — new correct 9/9, old
wrong on exactly two (the duplicate-row cases the reviewer named). Two
regressions: `TestLegacyStateUnattributedAllowsDuplicateManualConfigRows` (two
and three rows) and `TestLegacyStateUnattributedExcludesMixedIntentRows` (four
mixed sets, so "allow duplicates" cannot decay into "allow anything"). The file
holds twelve `TestLegacyState*` tests. `gofmt -l` clean, `go vet` clean on the
changed files, head `81fbce5c6`, 6 files **+1336/−0**.

### P2-7 — an unreadable config was an empty config

`configuredRepoPaths` collapsed three situations into `return nil`:

| situation | correct | what callers got |
|---|---|---|
| no repositories configured | nothing to check | nothing to check |
| config unreadable | **unknown** | nothing to check |
| config unparseable | **unknown** | nothing to check |

`config.LoadGlobal` already drew the line (`(gc, nil)` for missing, `(nil, err)`
for a parse failure); my reader discarded the error one line later.

**Fix:** `configuredRepoPaths() ([]string, error)`; the collector fails closed
(`Checked=false`, `Skipped` naming the cause); `doctorConfiguredPaths` changed
shape, so every stub and holder failed to compile — which is the point.

**Regression:** `TestLegacyStateConfigFailureIsNotAnEmptyConfig` covers **both**
formats. JSON: `checked` false, `skipped` carries the reason, no findings.
Human: names the global config, and **never** emits `no legacy state found`.
Thirteen `TestLegacyState*` tests now. Head `2df5cb4e7`, 6 files **+1422/−0**.

**Old vs new, side by side (harness):** old claims a completed check in both
formats; new reports the failure in both.

## 2. A gap in my own verification, found and closed

`go vet` reported clean on the rebased tree. It had never type-checked the test
files: the package fails on cgo grammar exclusions **before** the compiler
reaches them, so a missing `errors` import would have shipped.

Stubbing the four failing grammars (`cpp`, `swift`, `scala`, `kotlin`) let the
package compile far enough for the type checker to reach `_test.go` — and it
caught the missing import immediately. Stubs restored from backups; the tree is
clean apart from the two files the change touches.

**Rule:** when verification cannot reach the code you changed, it has not
verified anything. "vet was clean" meant only "vet got far enough to have
opinions".

## 3. `blixvip/NullMotion` #75 — the strip was last, so only the last route saw it

Issue #57: an instance mounted under `/null/` 404'd on every routed path while
`/` worked.

The prefix strip was the **final** statement in the request handler, after the
`/` and `/editor` rewrites, the `readOnly` table lookup, the template-source
route and the `/api/` guard had all been decided on the un-stripped path. Only
`serveFile` ever saw a stripped path — so `/null/api/...` failed the API guard,
`/null/editor` missed its rewrite, and `/null/` reached the file server as `/`
and served the **template gallery** instead of the homepage.

**Second bug in the same two lines:** `pathname = '/'` was assigned *after* the
`'/' -> '/demo.html'` rewrite, so normalising `/null` to `/` skipped the
homepage mapping.

**Fix:** normalise at the **top** of the handler, before the first comparison.
`/null` and `/null/` → `/`; `/null/<rest>` → `/<rest>`.

**Test:** `inherited /null/ path prefix is stripped before route matching` in
`test/server.test.js`; proven to fail on `origin/main`, pass with the fix.
Suite **41 → 42 tests, 40 pass / 2 fail** — both failures pre-existing and
identical on the unmodified base commit (audio extraction), unrelated.

**Manual curl:** all five routes 404 → 200; `/null` and `/null/` titles now
match `/`. PR: `blixvip/NullMotion#75`.
