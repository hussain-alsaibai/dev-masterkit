## New Tools Discovered & Verified

- **uv 0.13.5** — the Python environment tool that actually works on this
  container. Verified end to end: `uv venv` + `uv pip install` succeeds where
  `python -m venv` + `pip` fails. **Five** environment facts cost real time
  today, and each one wore a dependency costume:
  - **`/tmp` is `tmpfs ... noexec`** — a venv built there installs fine and
    then fails at import with `failed to map segment from shared object`,
    which reads like a broken wheel. The venv must live under `$HOME`.
  - **the repo needs Python >= 3.12** and the container ships **3.11.2** —
    3.11 cannot even *parse* `tests/conftest.py` (nested same-quote f-strings
    are PEP 701, 3.12+), so the error looked like a broken test file.
  - **`/tmp` was a 512 MB tmpfs at 86% full** (438 MB) with stale scratch
    dirs from a dead session. The original `npm install` failure was
    **ENOSPC**, not a dependency problem. Cleaning freed 436 MB.
  - **no compiler toolchain**: make, gcc, g++, cc are all MISSING, so a
    fresh `npm install` of `better-sqlite3` cannot build from source here.
    GitHub Actions runners have `build-essential`, so CI works even though
    the local install cannot.
  - **`node_modules/.bin` shims are not executable** in this container →
    `prebuild-install: Permission denied` and `npm run lint` → `eslint:
    not found`. Neither error mentions permissions. Invoke via
    `node node_modules/<pkg>/bin/*.js`.
  - `package.json`'s `"allowScripts"` is **not a real npm field** — npm
    ignores it.

## A loaded weapon, neutralised

`dev-masterkit-clone`, `dev-masterkit-check` and `dev-masterkit-sync` all
had `origin` pointing at the **real** GitHub repository and were 67-72
commits behind. The repo has **no branch protection and no ruleset**, so
`git push --force origin main` from any of them **would have succeeded**.

Dry-run diffs showed 210, 222 and 222 files would have been deleted,
including `.github/workflows/ci.yml` and every `daily-updates/` file after
2026-10-05.

Fixed by repointing all three remotes at
`file:///home/node/.openclaw/workspace/.disabled-remote/dev-masterkit.git`,
which does not exist — pushes now fail outright.

> **A backup clone of a repo you also push from is a loaded weapon.** Give it
> a different remote, or make it unable to push. Before deleting or
> force-pushing from any clone:
> ```bash
> git push --dry-run --force origin main
> git diff --name-status origin/main HEAD | grep -c '^D'
> ```
> A force push that reports *forced update* is fine. A force push that reports
> deletions is a catastrophe with a green checkmark.
