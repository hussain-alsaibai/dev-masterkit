# 2026-10-23 Daily Update

The day a cache method that everyone trusted turned out to hang forever, and a
scam filter that was supposed to stop fake bounties turned out to be
**armed and disarmed at the same time**.

`Cache.info()` deadlocked permanently — no error, no timeout, no traceback.
And the bounty's anti-scam filter was rejecting 161 of 348 issues correctly
while a rate-limit 403 made it read every fork farm as "clean". Both failures
were silent. Both had the same shape: **a signal that could not arrive was
being read as a signal that had passed.**

## New Repos Added

- **`tiny-hll` v0.1.0** — NEW. Zero-dependency HyperLogLog distinct counting.
  128 bytes fixed regardless of cardinality. Ships `merge()` so a global count
  can be built from per-shard partials without shipping raw data.
  Bias under 2.5% at every precision from 32 to 16384 registers, measured over
  12 independent sketches of 50,000 items; spread tracks 1.04/sqrt(m).
  **25 tests passing** (verified by run, 2026-10-23).
  https://github.com/hussain-alsaibai/tiny-hll
  **Repo does not exist upstream yet** (`https://github.com/hussain-alsaibai/tiny-hll`
  -> HTTP 404, 2026-10-23) — local clone only.

  **Why it exists:** the 2026-10-23 PyPI data. `datasketch` is flat at 4.3M
  downloads/mo; `pyprobables` grows 59% from 99.6K. The whole probabilistic
  category is ~0.4% of what `pytest` pulls. Developers want these structures
  and almost nobody imports a library for them — a Bloom filter is 80 lines and
  a dependency for it is a worse trade than writing it.

## New Tools Discovered & Verified

Grounded in the trends report above. **Last verified 2026-10-23.**

- **`fast-cache` v0.8.0** — fixed a **permanent deadlock** in `Cache.info()`,
  shipped stale-while-revalidate and key namespacing, and replaced a
  fabricated benchmark table with measured numbers. **54 tests passing**
  (verified by run). https://github.com/hussain-alsaibai/fast-cache

  The defect: `CacheStats.to_dict()` held a plain `threading.Lock` and then
  called `self.hit_rate`, which re-acquired the same lock. Every call hung the
  calling thread forever. Found because the legacy test suite also hung —
  `test_info` never returned; the suite printed all dots and stopped.

  Fixed with `RLock` + inline `hit_rate`. **Second instance of this bug class
  in two days** (the first was `tiny-mcp-registry`'s `export()`).

  Also shipped: `SwrCache` (per-key coalesced background refresh),
  `namespaced()` (key-prefix isolation), and a scalar fast path for size
  accounting. `set` 22K -> 57K ops/sec; hits 591K -> 1,445K.

- **`tiny-secret-mask` v0.5.1** — re-verified, **124/124 tests passing**
  (unchanged since 2026-10-21).

- **`tiny-router` v0.7.4** — re-verified, **177/177 tests passing** (unchanged
  since 2026-10-22).

## Key Lessons

- **A deadlock is a correctness bug with no symptom.** There is no exception
  to catch and no log line to read; the only evidence is that time stopped.
  Any code path holding a lock across a call it does not control needs a
  bounded test to prove it returns.
- **A gate that cannot distinguish "passed" from "not checked" is not a
  gate.** The anti-scam filter existed, was correct, and did nothing — because
  a rate-limit 403 and a genuinely empty repo were indistinguishable, and
  "no data" scored as "clean".
- **README accuracy is a growth lever, not housekeeping.** A fabricated
  benchmark table destroys the only asset a small library has, which is trust.
- **Assert invariants, not fixed values.** Three of the tiny-hll test
  assertions were wrong on the first run. The property-based framing is what
  surfaced them.
- **Thin is not dead.** 18 undated guides, 18 live repos. Verify existence
  before deleting; the expensive direction of that error is the delete.
