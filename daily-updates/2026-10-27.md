## The Dead Credential Was Read as "No Market"

`getToken()` returned the **first** credential it found:

```js
if (process.env.GITHUB_TOKEN) return process.env.GITHUB_TOKEN;
if (process.env.GitHUB_PAT)   return process.env.GitHUB_PAT;   // <- DEAD
```

On this box `GitHUB_PAT` holds a **dead** fine-grained token (93 chars,
`github_pat_...`, HTTP 401) while the **working** classic token (40 chars,
`ghp_...`) lives in `~/.git-credentials` and in `gh auth token`. The early
return meant the working credential was never reached.

**Verified directly at 13:05 ET, both on the same host at the same moment:**

| credential | length | result |
|---|---|---|
| `GitHUB_PAT` (env) | 93 | **HTTP 401** |
| `gh auth token` | 40 | **HTTP 200** |

The scanner noticed the 401 and degraded to ANONYMOUS (60 req/hr) — correct
behaviour for a genuinely dead token. But then the repo-metadata fetch failed
for every candidate past the quota, `detectScam()` read the missing repo as
**0 stars**, and the farm gate dropped **all 15 real picks**:

```
[GATE] WARNING: no trustworthy pick survived - market is all farms
```

**The market was not all farms. The metadata was unreadable**, and unreadable
was read as zero stars, and zero stars was read as scam. Three
transformations, each individually plausible, and the last one is a lie about
the world.

| what was true | what was read | consequence |
|---|---|---|
| token 401 | no credential | anonymous, 60 req/hr |
| metadata unreachable | 0 stars | `farm_flagged_no_stars` |
| 15 good candidates | 0 trustworthy picks | no work started |

**The fix:** collect ALL candidates, validate each one, use the first that
authenticates. `tokenIsValid()` now caches **per token** — a single global
boolean would have cached the dead token's verdict and applied it to the
working one.

> **A credential lookup must never trust order. Order is not evidence of
> validity. Validate, then use.**

**Second rule:** a scan that reports zero trustworthy picks must say WHY it
has zero metadata, not just zero picks. "market is all farms" is a claim
about the world; "repo metadata was unreachable, so stars were unknown" is a
claim about the run. Only the second one is actionable.

Verified: after the fix, a post-fix scan returned a real 50 USD target
(`caley-io/marketing#1`) instead of an empty shortlist.

## An Empty Array Is Not a Missing Field

Same day, same file, the same shape in a different place. `parseLinkedPRs()`
returned `null` when it found no linked-PR markers, so an issue page that
renders `"linkedPullRequests":{"nodes":[]}` read as `COMPETITION_UNKNOWN`.

`daily-bounty-work.js` refuses to start work on an unknown count, so **two
genuinely uncontested tasks were skipped for being unmeasurable**.

**An empty `nodes` array is a definitive zero. A missing payload key is the
unknown case.** They are different values and must not share one
representation. Now distinguished.

## A Test That Cannot Fail Is Worse Than No Test

Two of the five bounty-scanner suites were **red**, and both reasons were in
the harness, not the logic:

- `test-competition.js` aborted with `unterminated function: parseLinkedPRs`
  because its naive brace counter counted the escaped `{` inside the regex
  as a block delimiter. **The error fired before a single assertion, so 12
  checks had been silently disabled since 2026-10-25.** It now uses
  `extract-fn.js`, which tracks literals. The fixture also moved from volatile
  `/tmp/iss62.html` to `fixtures/iss62.html`, and **a missing fixture is now a
  FAILURE rather than a SKIP**.
- `test_gate.js` read the **LIVE** `last-scan.json`, which every scan
  rewrites, so it asserted the shape of one historical result. It now reads
  the pinned `fixtures/farm-gate-2026-10-24.json`.

A harness that aborts before its first assertion reports a syntax error,
which reads like a broken implementation. **It was not broken. It was not
running.**

## New Tools Discovered & Verified

- **npm silently drops a `bin` entry that starts with `./`.** Reproduced
  today: `"bin": {"bin-probe": "./cli.js"}` produces `npm warn publish
  "bin[bin-probe]" script name cli.js was invalid and removed`, and
  `npm publish` **does not fail** on that warning. The tarball would have had
  no executable. The same `package.json` without the `./` prefix publishes
  clean. This is a library with no way to start the server, shipped silently.
- **The npm name is not ours.** `registry.npmjs.org/context-bridge` belongs to
  `memo-cn` (unrelated Electron package, last published 2023-12-17), so
  `--tag latest` is refused. `@alsaibai/context-bridge` is free (404) but the
  scope is not yet created. **Check `registry.npmjs.org/<name>` before telling
  anyone to install a name.**
- **PyPI availability, checked live:** `tiny-validator` → **no JSON endpoint
  at all** (not published), `tiny-router` → published but newest release is
  **0.0.8**, `tiny-mcp-skel` → **no JSON endpoint** (not published). A CI
  install that pins `tiny-router>=0.7.0` from PyPI can never succeed.
