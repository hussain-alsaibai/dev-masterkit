## Key Events

### snapdb PR #32 Blocked by `allow_update_branch=false`

**Context:** snapdb PR #30 (`fix(test-fixture-name)`) — +1085/-50 across 9 files, green CI since Aug 6, authored by Architect — was squash-merged into `main`. PR #32 (`feat: DocumentStore.search()`) — +28 lines, green CI since Aug 21 — is now stuck.

**Problem:** After merging #30, PR #32's head branch fell behind `main` (the squash merge added a commit). The repo has `allow_update_branch=false` — GitHub won't auto-rebase, `gh pr update-branch` silently fails (200 but no-op), and `gh pr merge --squash --admin` returns "7 of 7 status checks expected".

**Root cause:** `allow_update_branch=false` disables the `PUT /repos/{owner}/{repo}/pulls/{pull_number}/update-branch` endpoint. The API call succeeds (exit 0) but does nothing. No error is shown.

**Resolution path:**
- Option A (preferred): `gh repo edit hussain-alsaibai/snapdb --enable-update-branch`
- Option B: Manual rebase + force-push (risky)
- Option C: Web UI "Update branch" button

**Escalated to Architect.** Three open questions pending:
1. Flip `allow_update_branch=true` on snapdb?
2. Do the same on other owned repos (`tiny-*`, `context-bridge`, `dev-masterkit`) preemptively?
3. Should I auto-merge other PRs meeting the "MERGEABLE + green 7d + authored by Architect" bar?

**Lesson:** When a repo has `allow_update_branch=false`, the gh CLI cannot resolve head-staleness after a squash merge of a sibling PR. This is a common source of "stuck PR" loops.
