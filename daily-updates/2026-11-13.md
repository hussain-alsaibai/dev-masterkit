## 1. A raw string cannot escape its own quote

```python
match = re.match(r\'\[(\w+)\]\s*(\w+):\s*(.+)\'', line)   # SyntaxError
```

In `r'...'` the backslash does not escape, so the quote closes the literal.
`ruff` reported 10 cascading `invalid-syntax` errors across lines 41-59, which
reads like a broken file; it was one broken literal.

The first repair produced `r'\[\(w+)\]...'` — the group `(\w+)` lost its
backslash and became a literal `(`. It parses and matches nothing, so every
`[HIGH] security: ...` finding fell through to the unstructured branch as
`severity=info, category=general`. **Cannot import became imports and quietly
mislabels everything**, which is worse.

Proved by behaviour: `_parse_response('[HIGH] security: SQL injection in login')`
→ `('HIGH','security','SQL injection in login')`. Restoring the broken pattern
→ **9 of 22 tests fail**; correct → **22 pass**.

Prompt: `prompts/a-raw-string-cannot-escape-its-own-quote.md`.

## 4. A CI workflow on a branch that does not exist is not CI

`unzip-http` was listed among the repos with no CI. It was not missing CI — it
had `.github/workflows/main.yml`, and CI had **never run once in the repo's
life**. The trigger named `master`; the only branch was `fix-readme-typos`.

```yaml
on:
  push:
    branches:
      - master        # <- a branch that does not exist
```

Two more problems behind it: `python setup.py develop` (removed from modern
setuptools) and a test step fetching a hardcoded external ZIP over HTTP.

The check is `gh run list --repo O/N` — **empty output is the finding**. Then
`gh api repos/O/N/branches` for the remote branch names; the local branch name
is not the remote's. `NO_CI_WORKFLOW` in a health report means either "no file"
or "never ran"; check the runs.

Fixed with 13 tests over a local `ThreadingHTTPServer` serving a real zip and
honouring `Range` requests — deterministic, no network, exercising the one thing
the library exists to do. Matrix 3.8-3.13, which is what proves the
`python_requires = ">=3.8"` claim.

Near-miss recorded: six tests were written against a `read()` method that does
not exist (the API is `open(fn)` + `extract()`); 6/10 failed and every failure
was the assumption. Grep the class for `def` first.

Prompts: `prompts/a-ci-workflow-on-a-branch-that-does-not-exist-is-not-ci.md`,

## 5. Export is half a contract

`tiny-validator` 0.7.1 and `tiny-config` 0.4.1 audited. Four drift classes, all
**permissive** (the direction that ships silently):

| library | exported | validator did |
|---|---|---|
| validator 0.7.1 | `Slug`/`Regex`/`HexColor` -> bare string | rejected `"Not A Slug"` |
| validator 0.7.1 | `IP(version=4)` -> no `format` | rejected `999.1.1.1` |
| validator 0.7.1 | `format: ipv4` imported as `String` | accepted `::1` |
| config 0.4.1 | masked `secret_ref`, `tokenizer` | hid the Vault path |
| config 0.4.1 | kept `db_password` | logged the credential |

The `IP` row was correct in the export and lossy in the **import** — an
export-only assertion would have been green on a broken round trip. The test is
`export -> import -> REJECT`: assert the corpus entry is invalid against the
original, then assert it is still invalid against the round trip.

Two standing rules fall out of it: **after adding a constraint-recording
mechanism, grep every `add_validator(` call** (`set_constraint` covered `String`
and `Integer`; `Slug`/`Regex`/`HexColor` kept pre-mechanism closures), and **a
format the library cannot enforce must not be exported** (no standard tag spans
IPv4+IPv6).

For secret names, a substring is the wrong operator: `key.lower() in SECRET_WORDS`
masked `secret_ref` *and* kept `db_password`. Equality OR **suffix** — suffix
because `db_password` names the secret and `password_file` names a path. Pointer
values (`vault://`, `awssm://`, `op://`, `env://`) and empty strings pass
through even under an explicit `redact=` entry: masking a pointer destroys the
incident record, not the secret.

Prompt: `prompts/a-roundtrip-tests-consistency-not-correctness.md`.

### The rule this adds

**When you correct a number, grep for every other copy of it before you commit.**
The same defect was written up this morning as *a check that could not have run
looks exactly like a check that passed*; this is the neighbouring shape: a
corrected claim looks exactly like a verified one. The correction and the stale
copy were in the same paragraph group and the diff was reviewed line-by-line,
which is precisely how you miss the line you did not touch.

The fix also re-derives `ls skills/ | wc -l → 49` from the five no-`SKILL.md`
directories rather than repeating the earlier explanation, which attributed the
extra count to `skills/AGENTSKILLS_PENDING.md`. That file is not why 49 ≠ 44 in
this tree; the five legacy directories are.
