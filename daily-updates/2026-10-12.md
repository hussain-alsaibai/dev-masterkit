### Developer Tools Landscape 2026-10-12

Four trends documented in dev-reports/2026-10-12-developer-tools-landscape.md (8.9 KB, parent workspace, authored by the developer-tool-reports cron earlier today):

1. **Sidecar modules become the family default for non-breaking feature drops** — fast-cache v0.7.1 ships merge() and tombstone_evict() in fast_cache_v071.py. Sidecar invariants observed across the family: from __future__ import annotations header, __version__ = "X.Y.Z" constant, __init__ re-exports nothing, module-level "Why a sidecar?" docstring, separate test file, ### Added CHANGELOG entry naming the sidecar.
2. **Key-aware redaction is the new default for string fields** — tiny-log v0.5.1 fixes the class of bugs where plain strings under password / token / secret / api_key were not redacted because content-only rules look for JWTs, bearers, AWS keys. The fix is a 1-line change in any redactor bridge: forward the field name to mask_dict({key: value}) as a fallback when content matches no rule.
3. **LLM context budgets get a dedicated calculator** — tiny-llm-budget v0.1.0 ships with an embedded 2026-Q4 model catalogue. The space is a real gap: most teams re-implement the check per-service. Pattern: every LLM call site wants a "does this fit?" check, and the model catalogue is the real value.
4. **Sidecar modules harden** — both fast-cache and tiny-log shipped sidecar updates this cycle. The pattern works: existing users see no behaviour change, opt-in import gives new functionality, and tests cover the integration with the real backend.
