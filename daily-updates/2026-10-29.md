# 2026-10-29 Daily Update

One thing happened today, and it was the shape we keep meeting: **a file that
stopped working, and nothing was watching it.**

NVIDIA shipped SkillSpector v2.13.2 yesterday. Our suppression baseline was
written for v2.13.1.

## A Baseline That Silently Stopped Suppressing

SkillSpector lets you accept the findings a human has already reviewed, so a
re-scan reports only what is *new*. That acceptance list is a YAML file of
fingerprints, and every fingerprint is bound to the scanner version.

So the upgrade invalidated every entry at once:

| Scanner | Baseline says | Unsuppressed | Suppressed |
|---|---|---|---|
| v2.13.1 (matches) | 2.13.1 | 65 | 62 |
| v2.13.2 (drifted) | 2.13.1 | **124** | **0** |
| v2.13.2 + regenerated baseline | 2.13.2 | 0 | 124 |

A scan of our 37 skills reported 124 findings and scored **100/100 CRITICAL,
"DO NOT INSTALL"**. Every one of them was a false alarm — all 124 had been
reviewed and accepted by hand on 2026-10-27. The worst "vulnerability" was a
documented cross-reference between two of our own skills.

**Three reasons it was invisible, and all three were ours:**

1. The baseline was **gitignored**. The comment said it was local state and
   "no CI in this repo consumes it". That was true, and it was the problem.
2. **No CI job read the baseline**, so no scan ever ran against it.
3. SkillSpector's behaviour is correct. A stale baseline is *supposed* to
   report everything. It cannot know the findings were previously accepted.

A tool cannot tell you that your suppression list has gone stale. Only a
version check can.

## The Fix

- **Regenerated the baseline against v2.13.2**, carrying every human review
  reason across by (file, rule) pair — 115 preserved verbatim, 9 new pairs
  reviewed by hand. The old file is kept at
  `memory/skillspector-baseline-dev-masterkit-2026-10-27.yaml.bak-2.13.1`.
- **Stopped ignoring the baseline.** It is a record of human decisions and it
  only works if it is versioned with the skills it describes.
- **Added `scripts/scan_skills.py`** and a `skill-security` CI job that fails
  when the scanner version drifts from the baseline, and fails when any
  finding survives it. Both paths were tested locally, not assumed:
  - version mismatch → exit 1 with an actionable message;
  - clean scan → exit 0, "0 unsuppressed, 124 suppressed, risk score 0 (LOW)".

## Also Found

The scan flagged **`SC8`/`SC9`** — a skill shipping a `__pycache__` directory
with compiled bytecode. Git never tracked it, so it was never published, but it
was on disk and being scanned as a concealed executable artifact. Removed.

## The Rule

**A suppression list needs a version check, and a gitignored baseline is a
baseline nobody watches.** Both of ours were true at once, which is why a
scanner upgrade looked like 124 new security problems.
