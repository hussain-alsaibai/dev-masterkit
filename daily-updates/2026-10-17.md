# 2026-10-17 — Input safety + browser boundary day (tiny-input-sanitize + tiny-cors)

## Theme

The two surfaces where untrusted text meets your process: the agent tool argument
that becomes a shell command, SQL literal, or filename, and the browser request
that needs a CORS handshake. Two new tiny-* repos today, both ~400 LOC stdlib-only,
both fully tested. The dev-masterkit local HEAD is now 19 commits ahead of
origin/main (day ~30 of GitHUB_PAT 401).

## New repos (2)

- **tiny-input-sanitize v0.1.0** — allowlist-first input sanitization. 6 contexts
  (HTML, SQL, shell, filename, log, JSONPath), confidence scoring (0.0–1.0),
  `allow`/`deny` composition, NFKC normalization (catches homoglyph attacks),
  `SanitizationResult` dataclass. 49 tests, MIT, 398 LOC, zero deps.
  https://github.com/hussain-alsaibai/tiny-input-sanitize
- **tiny-cors v0.1.0** — RFC 9110 / Fetch CORS-compliant WSGI + ASGI middleware.
  Wildcard+credentials auto-handled, `Vary: Origin` on every response,
  `PreflightCache` with TTL, `tiny-router` integration helper, regex subdomain
  matching. 23 tests, MIT, 425 LOC, zero deps.
  https://github.com/hussain-alsaibai/tiny-cors
