## What shipped today

### A guard that passed while the package drifted seven releases

| repo | guarded pair | unguarded surface | drift |
|---|---|---|---|
| `snapdb` | `pyproject.toml` ↔ `__version__` | `package.json` | **7 minor** (`0.11.0` vs `0.18.0`) |
| `tiny-router` | none | `package.json` vs shipped | **5 minor** (`0.2.0` vs `0.7.5`) |

`snapdb` **had** a version-consistency test. It compared the two files its
author was thinking about, validated semver, and passed. The file that drifted
was the one nothing read.

Both are fixed on `main` (`fix: package.json said 0.11.0 while the package
shipped 0.18.0`) and both now fail a test if the pair drifts again.

### The census: 19 manifests nothing reads

- **0** of those 19 are published to npm.

A manifest that no build step, CI job or test opens cannot fail. That is the
whole mechanism.

## The script's own tests found two bugs before it shipped

- The first normaliser stripped **every** pre-release tail, so `1.0.0-rc1`
  compared equal to `1.0.0`. A normaliser that strips every tail calls a release
  candidate equal to the release it never became. Tails are now kept.
- It rejected `1.4` vs `1.4.0`. A two-component core is now padded to three.

Both were caught by tests written with the script, which is the argument for
writing them in the same commit.

## The rules this day adds

> **A version stated in more than one file is a version stated once and guessed
> everywhere else.**

> **A guard is a claim about coverage.** It is only as wide as the list of files
> it opens; the file that drifts is usually the one nobody added to the list.

> **A manifest nothing reads cannot fail, and so it cannot be noticed.** An
> unread `package.json` also publishes someone else's package name silently.
