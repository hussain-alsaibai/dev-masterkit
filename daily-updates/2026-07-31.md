### GitHub PAT Scope Problem (Confirmed)

**Root cause:** `hussain-alsaibai` FG-PAT has `pull` only on upstream repos.
- ✅ Can clone public repos
- ✅ Can push branches to forks
- ❌ Cannot create PRs from fork → upstream
- ❌ Cannot comment on upstream issues

**Fine-grained PATs are per-repo**, not global. A PAT scoped to your repos cannot act on external repos.

**Workaround:** Architect must open PRs manually via GitHub web UI.

### New Prompt: already-merged-skip
- **File:** `prompts/already-merged-skip.md`
- **Core idea:** Always grep upstream before implementing any bounty. Check for merged PRs, existing implementations, and issue body language.
- **Key rules:**
  1. `gh search prs --repo owner/repo --state merged --match "issue:XXX"` before starting
  2. `git log --grep` on upstream for the feature name
  3. Read the issue body — some say "PR #XXX finalized" in plain text
  4. The 30-second grep saves 2 hours of wasted work
- **Real cases:** Palm2 (PR #614 merged Jun 15), AWS Comprehend (local implementation from Jul 16, 2024), ActivePieces (issue body says "PR #8083 finalized")
- **Last verified:** 2026-07-31

### New Prompt: bounty-pat-write-access
- **File:** `prompts/bounty-pat-write-access.md`
- **Core idea:** Fine-grained PATs cannot open cross-fork PRs. Document the three-layer PR access model and the manual web UI workaround.
- **Key rules:**
  1. FG-PAT = per-repo permissions, not global
  2. Fork → upstream requires explicit upstream permission in the PAT scope
  3. Classic PAT with `repo` scope could do it, but FG-PATs are more restrictive
  4. Always verify with `gh pr create --repo owner/upstream --draft` before starting
  5. Manual web UI bypasses PAT entirely
- **Last verified:** 2026-07-31
