## The defect

The client parsed the `initialize` result and then ignored the `capabilities`
object inside it. The MCP spec is explicit: a capability that is absent from
that result means *not implemented*. So the client called `tools/list` on
servers that never claimed `tools`, and the miss arrived as

```
MCPError: [Errno -32601] Method not found
```

— an opaque error at call time, for a contract violation that was already
knowable at `initialize` time.

## Why the suite did not catch it

The guard **fails open**. Remove it and every happy-path test still passes,
because a happy-path test exercises servers that *do* advertise the
capability. The suite grew 33 -> 40 and the seven new tests are mostly
rejections — but rejections alone are satisfied by a client that blocks
everything, so one of the seven is a **positive control**.

The proof that matters is the mutation:

| step | result |
|---|---|
| `_require()` replaced by the old bare "not initialized" branch | **5 failed, 35 passed** |
| guard restored | **40 passed** |

A guard nobody has watched reject something is a comment with a control flow.

## The server side is still open

`tiny-mcp-server` (`16 passed`, fresh clone) implements `tools/list` and
`tools/call` unconditionally, and answers a request for `resources/list` with
`-32601 method not found` even though its own `initialize` and
`server/discover` results advertise only `{"tools": ...}`. **Measured, not
inferred:**

```python
s.handle_message({"jsonrpc": "2.0", "id": 3, "method": "resources/list",
                  "params": {}})
# {'jsonrpc': '2.0', 'id': 3,
#  'error': {'code': -32601, 'message': 'method not found: resources/list'}}
```

That is the same defect class in the other parser: the right answer is
`MCPCapabilityError`-equivalent naming *the capability it never advertised*,
not a method-not-found that sends the caller looking at its spelling.
Recorded as a measurement; no server change was made in this run.

## Addendum (13:1x EST) — the RED fix that was applied and still wrong

**Last verified:** 2026-11-07 (13:10 EST) — the fleet was re-swept with
`node repo_health_check.js` after the fix below, and the entry above's census
numbers were re-confirmed unchanged.

### What happened

The 2026-11-06 fix (`the-last-five-runs-are-not-the-default-branch`) introduced
`latestBad` — the newest completed run **on the repo's default branch** — and
rewrote the summary line to count `latestBad`. But the line that actually
assigned the status was left as:

```js
if (latestBad || failingRecent.length > 0) { status = 'RED'; }
```

`failingRecent` is *any bad run since the previous check* — precisely the window
rule the previous entry bans. So the commit read as a complete fix, and the bug
survived a day.

**Live symptom.** `tiny-dist-audit`, on its first sweep after creation, was
reported **RED / "CI failing (main, 2026-11-06)"** while `main` was green:

| run | time (UTC) | conclusion |
|---|---|---|
| `0420616` | 13:05:29 | failure |
| `5b9f4ff` | 13:07:00 | failure |
| `0b4c8fe` | 13:08:30 | **success** (invoke the module, not a console script) |

Three pushes to `main` in three minutes; the last repaired what the first two
hit.

### The fix

- RED is set by `latestBad` **only**.
- `failingRecent` is retained but reported as `recoveredCi`, with the superseded
  runs and the green run attached. A recovery is information, not a status.
- Staleness stays out of the predicate: 46 repos carry a
  successful-but-stale newest run (9–12 days; `tiny-rbac` 101 days). Cadence
  signal, never failure.

### Rules this adds

> **A fix that changes the inputs to a decision without changing the expression
> that makes the decision is not a fix.** Grep the old predicate; if it still
> reaches a status, you shipped a comment.

> **A predicate whose name says "recent" will eventually be read as a state.**
> Name it for the window it measures and keep that window out of any status
> assignment.

> **A repo's first sweep is the best available detector of window bugs** — new
> repos fail and recover within minutes, so "recent failures" fires while the
> actual state is green.
