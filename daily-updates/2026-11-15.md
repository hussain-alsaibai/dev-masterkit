## 1. `gortex` #1418 — two P2 findings from the maintainer, both real

Reviewed on `4a31f7a3e`, raised as P2-4 and P2-5, fixed on
`doctor-legacy-state` (`e1185a5a0`), PR **MERGEABLE**.

**P2-4 — the redactor leaked everything it did not own.** `doctorPath`
rewrote paths under the repo root and under home, and returned the rest
verbatim with the justification *"outside both roots: no name of ours to
leak"*. True for paths the report synthesised; false for the legacy-state
census, which is **daemon-wide** and reports checkouts in sibling homes and
on other mounts. Reproduced by the reviewer through the real collector and
redactor, in both JSON and human output under `--redact`. Fixed with a
separate `newDoctorRootRedactor` that aliases every reported root to
`<root-N>` wherever it lives — ordinal, so it leaks neither length nor shape
— installed through its own seam so non-redacted output is unchanged.

**P2-5 — an exclusion list masquerading as a classification.**
`hasRecordedIntent` was `cli_track || mcp_track`, against a four-member
intent universe. A checkout tracked purely by `project_membership` — known
provenance, one of the strongest signals available — fell through to
*unattributed* and was offered an auto-indexed heuristic and a remediation
for a problem it did not have. Fixed with `isManualConfigOnly`: unattributed
means the set is **exactly** `{manual_config}`.

**Verified without a build** (`go test` still excludes 198 cgo
build-constraint files here, so nothing in that package compiles): `gofmt -l`
empty on all 5 changed files; `go vet` zero errors from those files beyond the
exclusions; and a Go harness carrying the functions verbatim — **17/17 pass
post-fix, 4 failures pre-fix** (2 roots leaked verbatim, 2 intent sets
mislabelled). Both counts went into the PR reply.

## 2. `snapdb` — a published speedup that reproduces as a slowdown

The README and changelog claimed **31.5× on a 50K-row narrow range** for the
v0.18.0 `RangeIndex` planner. Re-measured across selectivities:

| rows matched | share | scan | index | speedup |
|---:|---:|---:|---:|---:|
| 30 | 0.1% | 24.7 ms | 0.15 ms | 169× |
| 505 | 1% | 25.7 ms | 0.97 ms | 26× |
| 2,505 | 5% | 25.4 ms | 4.6 ms | 5.5× |
| 10,005 | 20% | 27.3 ms | 19.3 ms | 1.4× |
| 20,005 | 40% | 31.7 ms | 29.7 ms | 1.1× |
| 40,005 | 80% | 37.8 ms | 35.7 ms | 1.1× |

The stated shape gives **26×**, and 31.5× is reachable only near 0.4%. At 80%
the index path is **0.4×** — a user who added an index made the query slower,
having read a README that promised 31.5×. Cause: index results cost one random
row decode each against a sequential scan, and no plan guarded that.

Fixed (`6fd005a`): `execute()` estimates touched rows with two bisects and
rejects the plan above 30% of the table; `explain()` reports the plan
execution will use and the rejection reason
(`Scan(filter=['age']) [index rejected: 62/100 rows]`). **244 passed, 9
skipped**, CI green, and **5 of 8 new tests fail against the unfixed file**.

## 3. Install lines — the census regex was the reason 12 survived

Yesterday's sweep fixed 46 READMEs; 12 still advertised a bare
`pip install <name>`. The census regex required the package name to **end a
word**, so extras (`pkg[fast]`), three-package blocks, in-sentence claims and
non-README docs were all invisible to it. All 12 fixed and each verified with
`pip download`, not by reading the diff. The 5 remaining hits are warnings
that quote the broken command. The guard now understands URLs as well as bare
names.
