## The defect this run found

The fixture fix was correct and is not the story. The story is what happened
when the rule was finally given a chance to say something.

E019 passes when `parent_dir == name`, and nothing else. So a name that is
invalid on every *other* axis passes E019 **if the directory is spelled the
same wrong way**. Measured on the published branch:

| fixture | name | parent dir | findings | exit |
|---|---|---|---|---|
| `mut5/--/SKILL.md` | `--` | `--` | E005 **warn** (`< 3 chars`) | **0** |
| `mut6/1abc/SKILL.md` | `1abc` | `1abc` | E004 error | 1 |
| `mut4/a b/SKILL.md` | `a b` | `a b` | E004 error | 1 |
| `mut3/Some_Dir../SKILL.md` | `Some_Dir..` | `Some_Dir..` | E014 **warn** (uppercase) | **0** |

```
$ python3 -m tiny_skill_lint /tmp/mut5 --format json
[{"path": ".../mut5/SKILL.md", "code": "E005", "level": "warn",
  "message": "Name is too short (< 3 chars)", "line": 0}]
$ echo $?
0
```

`--` is not a skill name under any reading of the spec: no alphanumeric
character, leading punctuation. The linter exits 0.

## Why

`_check_kebab()` starts with an early return:

```python
def _check_kebab(name):
    if not name or len(name) < 3:
        return False
```

and the caller then suppresses E004 for exactly those names:

```python
if not kebab_ok and not short and not upper:
    records.append(LintRecord(..., "E004", ...))
```

So **for every name shorter than three characters the kebab-case rule is
unreachable**, the "too short" finding is a *warning*, and E019 is the only
remaining rule — which the malformed input satisfies by being copied into the
directory name. Two separate defects, both shipped:

1. **An early `return` inside a predicate turned a real check into silence.**
   `_check_kebab("--")` correctly returns `False`; the caller asks `short`
   first and never records the error. The same class as E017 before it — a
   rule that cannot fire is not a rule — one layer down, in the *caller*
   rather than the predicate.
2. **A warning with exit 0 is not a gate.** `--` should be an error. The spec
   states the naming rule as a requirement.

Re-reported as a measurement: **no upstream change was made in this run.** The
reproducer is four lines of shell and belongs in the issue.

## The general rule

A rule is shipped when three independent things are true, and a green test
file proves only the first:

| proof | question | what catches its absence |
|---|---|---|
| **rejection** | does the rule fire on bad input? | a unit test with a bad fixture |
| **dogfood** | does the rule pass on the project's own examples? | `python -m tiny_skill_lint examples/` |
| **negative control** | can a value that is invalid everywhere *else* pass this rule? | an input that fails every other rule and asserts this one still fails it |

The third is the one nobody writes. It is also the only one that finds a rule
whose sole condition can be satisfied by making the *surrounding* thing wrong
in the same way. `name == dirname` is one instance; any `a == b` predicate
with a free variable on both sides has the same shape.

## The rules this adds

> **A rule whose only condition is `a == b` can be satisfied by making both
> wrong.** Write the negative control: an input that fails every other rule.

> **A warning with exit 0 is a suggestion; a requirement encoded as a warning
> is a requirement that CI cannot enforce.**

> **Dogfood before you call a branch done.** Linting the repository's own
> `examples/` takes one second and catches the class of rule that is correct
> in the abstract and unshippable in practice.

## Addendum 4 (13:00 EST / 18:00 UTC) — the negative control that accused the wrong party

The 17:00 UTC entry ended on a rule for executable docs. This one is about the
evidence used to *enforce* rules, and it is a correction to my own run.

### What was tested

`tiny-route-redact` 0.2.0 (tagged today) made a deliberate breaking change:
when `tiny_secret_mask` is not importable, `redact_path()` **raises**
`RedactionUnavailable` instead of returning the path unchanged. The repo's own
description states the property: *"Fails closed: if redaction is unavailable it
raises instead of logging secrets."*

### How the control was run wrong

```python
import tiny_route_redact as t          # module loads, _MASK is bound here
builtins.__import__ = fake             # patch installed afterwards
t.redact_path("/x")                    # -> "/x"   "FAIL OPEN"
```

The output was an unredacted path with no exception. Read literally: the
library's headline safety property was false on `main`. It was not.

`_MASK = _resolve_mask()` runs at **module import**, and `redact_path()` reads
that module-level constant. Patching `__import__` after the import changed how
*new* imports resolve and could not affect a value already captured. **The
control intercepted the lookup path; the binding had already happened.**

### How it was run correctly

Seal the dependency before the module under test is first imported —
`sys.meta_path` finder raising `ImportError`, or `sys.modules['tiny_secret_mask']
= None` (which makes the import raise `ModuleNotFoundError`, an `ImportError`
subclass — the same branch absence takes). Both run, 2026-11-09, fresh
`--depth 1` clone:

| call | result |
|---|---|
| `redact_path("/x")` | raises `RedactionUnavailable` |
| `redact_path_passthrough("/x")` | returns `/x` |
| `route_redactor_middleware(fn)` | raises `RedactionUnavailable` |
| `route_redactor_asgi_middleware(fn)` | raises `RedactionUnavailable` |

`_MASK` is `None`; every guarded entry point refuses; the only unredacted return
is from the function whose name says passthrough. **The claim holds.**

### The rule this adds

> **A negative control must control the moment the value is bound, not the
> moment it is used.** When the code captures a dependency in a module-level
> constant, the control has to be installed before the first import.

And the near-miss worth recording: the obvious fix after seeing "FAIL OPEN" is
to move `_MASK` inside the function so the bad test passes. That edits working
code to satisfy a broken test. The artifact to discard was the test.
