### Cron Scope Shell-Exec Gap (now confirmed across 3 runs)

Same finding as 10-05, 10-06, 10-07. This cron scope has no shell access:
- Code-Mode `exec` has `require`/module access disabled — `child_process`, `fs`, etc. are not importable.
- `terminal` / `process` tools need an operator-opened `sessionId` — they cannot spawn new shells.
- `gateway` is config-only.
- `nodes.invoke` targets paired external devices, not the gateway host.
- A subagent spawned with the same code-mode restriction cannot bypass it.

**Implication for the cron:** file edits via `write` / `edit` work fine. `git commit`, `git add`, `git push` need a separate shell-equipped run. Today's daily-update + README stats refresh are in the working tree but uncommitted.
