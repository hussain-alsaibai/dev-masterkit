## 1. The cached-`None` bug, twice, in two packages

`fast-cache` **0.9.1** (`d646559`) and `tiny-prompt-cache` **0.1.1** (`2e03b2c`,
merged `d51e093`) both shipped a fix for the same defect on the same day. The
defect: a cache whose hit test is `value is not None` treats a cached `None` as a
miss and re-runs the factory.

`tiny-prompt-cache` had the worse variant — `get_or_call` ran `len(response)`
**before** storing, so a `None` LLM response raised `TypeError` on the **first**
call. A cache that cannot cache a value the backend is free to return. Fixed with
a `_MISSING` sentinel, a public `has()`, and the size computation moved behind
the hit test.

Measured here:


## 3. Third occurrence of the shape this month

| package | fixed path | unfixed path |
|---|---|---|
| `snapdb` 0.18.3 | module-level function | class method |
| `fast-cache` 0.9.0 | `get_or_set` | `get_or_set_async` |
| `tiny-prompt-cache` 0.1.0 | v1 `get_or_call` | v2 module |

Three instances is the signal to sweep, not to patch. Grep the defect **shape**
(`is not None` as a hit test, `if cached:`, `len(x)` on an optional return), not
the method name — the method name is different in every one of the three.

## 4. Bounty scanner: three defects, found by hand-checking one candidate

The 12:00 run's sister job hand-checked `crewAIInc/crewAI#8003` — a 61,153-star
org repo reported as an uncontested pick. It had **five** open PRs. Three
separate defects fell out:

- **`stars` was not this repo's stars.** A candidate's `stars` can carry a
  shared/derived value, and the reject message printed it as fact
  (`Repo has 0 stars`). Print the field *and* its provenance, or print nothing.
- **The farm gate summed `no_stars` across a repo's issues.** Six issues in a
  61k-star repo and six in a 0-star farm produced identical input. Now computed
  once **per repository**, keyed by repo, with the true signature **forks**
  (0-1 stars, more than one fork) because fork counts are stable as waves shrink.
- **`>= 3` open PRs was the wrong competition floor.** Two independent
  implementations already open is not a vacancy. `MAX_COMPETING_PRS = 2`, and the
  worker's guards moved with it.

Recorded here because the general rule is reusable: **when a gate rejects
everything and the operator names one candidate that should have survived,
reproduce the gate's decision on that one candidate first.** One `gh issue view`
plus one cache read showed `count:5 → count:0`. Three scan reruns would not have.
