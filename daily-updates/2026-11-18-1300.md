## 1. A host that forbids execution looks like a failing suite

```console
$ python3 -m pytest -q
FAILED tests/test_scan_skills.py::test_local_venv_beats_path - SystemExit: 1
...
8 failed, 293 passed
```

The assertion that surfaces:

```text
assert 'does not match the baseline' in
  'FAIL: SKILLSPECTOR_BIN=/tmp/pytest-of-node/pytest-28/.../skillspector is not an executable file'
```

That message points at `scripts/scan_skills.py`, which is **correct**: it refused a
path it could not execute. The cause is the mount:

```console
$ grep " /tmp " /proc/mounts
tmpfs /tmp tmpfs rw,nosuid,nodev,noexec,relatime,size=524288k
```

`tests/test_scan_skills.py` writes a scanner stub into `pytest`'s `tmp_path` (under
`/tmp`), does `os.chmod(path, 0o755)`, and the script then checks
`os.access(override, os.X_OK)`.

| observation | value |
|---|---|
| `stat` mode | `0o100755` |
| `os.access(p, os.X_OK)` | **False** |
| `os.chmod` return | 0 (success) |

On a `noexec` mount, `access(2)` denies `X_OK` regardless of the mode bits. The mode is
right, the `chmod` succeeded, and the file still cannot be executed.

### The fix, and the non-fixes

```console
$ TMPDIR=$HOME/tmp python3 -m pytest -q
301 passed in 2.83s
```

`pytest`'s `tmp_path` honours `TMPDIR`; no test and no source changed. Reverted and
re-ran with the default `TMPDIR` to confirm the 8 failures return — they do.

Rejected:

- **Relaxing `os.access(X_OK)` to `os.path.isfile`.** Passes everywhere and stops testing
  the contract, which is "this path is directly executable".
- **Invoking the stub as `sys.executable stub.py`.** Proves the source parses; it does not
  test the resolution order the script exists to implement.
- **Calling it flaky.** 100% on this host, 0% on CI — an environment precondition, not
  nondeterminism.

### Why it matters beyond this repo

The same class hits any test that spawns a file it just wrote: CLI stubs, `gh`/`docker`
fakes on `PATH`, Playwright wrappers, git hooks. `noexec /tmp` is common on hardened
Kubernetes nodes, `docker run --tmpfs /tmp:noexec`, and CI sandboxes.
