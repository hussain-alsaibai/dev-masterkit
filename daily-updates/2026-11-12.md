## 1. A fix in one sibling is a bug report about the other

`tiny_router_redact_headers.py` was fixed on 2026-10-26 to raise
`RedactionUnavailable` rather than pass headers through. The fix commit's own
reasoning: *"a redaction layer that cannot redact must refuse."*

`tiny_router_redact_path.py` — same template, forty lines away — still had:

```python
if mask is None:
    return nxt(req)          # serve the request, forward the credential
```

A deployment could install the path middleware, believe URL segments were
scrubbed, and forward them verbatim. Nothing raised. The suite was green for
seventeen days **because every test had the dependency installed** — the absent
branch is only reachable by removing it.

The grep that finds this is the one you can write from your own fix commit:

```sh
grep -rn "return nxt(req)\|is None: return\|except ImportError" <repo>
```

## 2. An exporter must be checked by a third party

`validate()` reports a missing field only when
`field.required and field.default is ...`. `to_json_schema()` used
`field.required` alone, so `String(default="anon")` — optional at runtime —
was emitted into `required`.

The roundtrip test (`to_json_schema` → `from_json_schema` → `validate`) passes,
because `from_json_schema` marks the field required too. Both sides shared the
wrong assumption, so the errors cancel. **A roundtrip tests consistency, not
correctness.**

The check that catches it:

```python
library_ok = not schema.validate(payload)
try:
    jsonschema.validate(payload, to_json_schema(schema)); js_ok = True
except jsonschema.ValidationError:
    js_ok = False
assert library_ok == js_ok
```

New prompt: `prompts/an-exporter-must-be-checked-by-a-third-party.md`.

Both version guards (`test_version_consistency`) caught README badge and
`package.json` drift on the bump. They work — that is the one defect class that
can be caught by reading rather than executing, so it should never ship.

## 3. A compiler you cannot install is still a compiler you can verify with

A fork PR whose workflows sit in `action_required` has **zero evidence behind
its claims**. No gcc, no root, no apt in this container — and the build still
happened, via `zig cc`.

Three failures, each wearing a different costume:

1. **cgo probes the compiler on stdin** (`-x c -`); `zig cc` cannot read stdin,
   so every package failed the probe and reported *"build constraints exclude
   all Go files"* — which reads like a broken module tree. Fixed with a wrapper
   rewriting `-` to `/dev/stdin`.
2. **OOM read as a parser crash.** Zig 0.13 dies silently above ~50 MB. The two
   failing grammars of ~180 were exactly the two largest source files (84 MB,
   65 MB). 0.15.2 fixed nim; systemverilog dies at **1.2 GB RSS**.
3. **The Go linker needs `TMPDIR`, not just `GOTMPDIR`.** `/tmp` is a 512 MB
   tmpfs; the link hit `ENOSPC` *after* every grammar had compiled.

Result: `gortex v0.64.11`, 318.6 MB binary, `--help` clean, and the PR's own
claim executed — `go test -run 'Doctor|Legacy' ./cmd/gortex/` → **ok** (2.063 s).
The temporary stub used to get the build through was restored; `git diff` empty.

New: `prompts/a-compiler-you-cannot-install-is-still-a-compiler-you-can-verify-with.md`
and `tools/go-cgo-zig-toolchain-guide.md`.
