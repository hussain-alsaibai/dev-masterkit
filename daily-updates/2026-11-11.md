## 1. A test that only runs in a checkout is a test that never ran

`pytest` in the git checkout: green. `pytest` in an unpacked sdist of the same
commit: **2 failed, 2 errors**. Two causes, both invisible in a checkout:

- `test_version_consistency.py` read `CHANGELOG.md` and `package.json`; neither
  was in `MANIFEST.in`, so neither was in the tarball.
- `test_delta_encoding.py` and `test_dict_encoding.py` defined
  `def test(name, ok, detail="")` at module level — collected as a test needing
  a `name` fixture, so the file errored on **every** run including ours.

The suite that exists to prove the published version is consistent could not
run against the published bytes. New prompt:
`prompts/a-test-that-only-runs-in-a-checkout-is-a-test-that-never-ran.md`.

## 2. CI that is not auto-triggered is CI that ran once, by accident

`tiny-log`'s workflow ran seven files by name; the eleven regression tests for
the 0.8.0 `extra=` fix were never added to the list and never ran. `tiny-cli`
passed file-by-file and failed as a suite, because `_NO_COLOR` latches at import
from `isatty()` + env and the test modules set the override in their module
body — alphabetical collection imports `test_completion.py` first and latches
the wrong value.

Both are invisible from a green badge. New prompt:
`prompts/ci-that-is-not-auto-triggered-is-ci-that-ran-once.md`.

## 3. A witness the writer can repair is not a witness

`tiny-audit`'s `verify()` checked `prev_hash` and the per-line HMAC. A
**truncated** log passed — the surviving lines chain and sign perfectly. This
is the cheapest tamper and the one an audit log exists to catch.

Fix: `seq` inside the HMAC (catches middle deletion and reorder as a sequence
gap) plus an optional `high_water_path=` sidecar.

**The first version of the fix was self-defeating.** The constructor wrote the
observed length into the sidecar unconditionally, so reopening a truncated log
overwrote the record of its real length and `verify()` compared the log to
itself. The write must be **raise-only**. New prompt:
`prompts/a-witness-the-writer-can-repair-is-not-a-witness.md`.

The limit is documented and pinned by a test: without the sidecar, truncation
remains undetectable.

## 4. A vendored directory is an undeclared build step

`claw-token` had 436 tracked `node_modules` files. `.gitignore` had the rule
since the first commit — but **ignoring a path does not untrack it**, and the
directory was committed in that same commit, so 443MB shipped in every clone.

Untracking turned CI red, and the cause was not a regression:
`foundry.toml` sets `libs = ["node_modules", "lib"]` and remaps
`@openzeppelin/` into it, so the vendored tree **was** the dependency install.
`forge build` had no install step because it had never needed one. Reproduced
from a clean tree (`git archive HEAD | tar -x`): identical `Error (6275)`. Fix
`1c00b63` adds `npm ci`. Second cleanup `0b22148` untracked 48 `out/` files
(build output) that `.gitignore` had missed while `cache/` and `artifacts/`
were already ignored.

New prompt: `prompts/a-vendored-directory-is-an-undeclared-build-step.md`.

## 5. A CI job with a credential and a side effect must not share a trigger

`deploy.yml` ran on **every push to main** with a live `DEPLOYER_PRIVATE_KEY`.
Two deployments 90 seconds apart — a contract fix, then a README address
update — each burning a new contract address, both now on-chain.

Fixed to `workflow_dispatch` with a required `reason` input, verified three
ways: the auto-commit of `deployment.json` triggered **zero** runs (GitHub does
not run workflows for `GITHUB_TOKEN` pushes), an ordinary push triggered
nothing, and the live contract answered `totalTaxBps()` → 300.

Because it is a pattern, it became a fleet check: `scripts/scan_push_to_main_side_effects.py`
over **499 workflows** (164 owned) found **no other hits**. The scanner's
self-test reconstructs the old workflow and asserts it is flagged — a scan that
cannot find a known bug reports clean no matter what.

New prompt:
`prompts/a-ci-job-with-a-credential-and-a-side-effect-must-not-share-a-trigger.md`.

## 6. A collision warning is not enough if the install command is still there

Three READMEs showed `pip install <name>` for names owned on PyPI by other
people: `tiny-memo` (meng), `tiny-eval` (a different eval framework),
`xvfbwrapper` (Corey Goldberg). The command **succeeds** and installs someone
else's program with no error. The warning was replaced by the git URL, which
always resolves to this project. `tiny-eval` needed a rebase rather than a
force push — a force push would have deleted 4 real files.

New prompt: `prompts/a-collision-warning-must-replace-the-install-command.md`.

## 7. Corrected: a throwaway environment is still an environment

`prompts/a-rerun-is-not-a-rerun-if-the-tempdir-was-full.md` said the delta
between a full-tmpfs run and an overlay run is proof of an environment defect.
That is only true if nothing else changed. Snapdb's sdist failure was real and
would have been dismissed by that rule: re-running it with `--basetemp` on the
overlay still fails, because the missing files are missing from the artifact.
Amended with the discriminator: **re-run in the same environment with the same
inputs before blaming the environment.**

## Tooling notes (verified this run)

- `uv build --sdist` works where `python3 -m build` is not installed.
- `PKG-INFO` is RFC-822 **without** a section header — `configparser` raises
  `MissingSectionHeaderError`. Parse `^Version:` with a regex.
- `mv` across filesystems copies then deletes; moving a large `node_modules`
  through `/tmp` (a 512MB tmpfs) produced ~250 `ENOSPC` errors. Use
  `git archive` to get a clean tree.
- `git archive HEAD | tar -x -C /tmp/x` reproduces CI's checkout exactly (no
  `node_modules`, empty submodule) — the fastest way to tell code from
  environment.
