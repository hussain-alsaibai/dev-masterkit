## 1. A re-run is not a re-run if the tempdir was full

`hub/agents/email/python/tests/` reported **81 failed, 970 passed** with an

## 2. A `.so` that cannot map is not a broken wheel

Every binary wheel installed into `/tmp` failed with *"failed to map segment
from shared object"* — `sqlalchemy`, `cryptography`, `pydantic_core`, `lxml`,
`greenlet` — while every pure-Python package installed into the same directory

## 7. A cross-repo marker is a deletion predicate

Found while reviewing my own PR's Cursor paths: `_cleanup_cursor` and
`_patch_cursor` called `_is_observal_hook_entry(h)` with the **default** marker
set, whose last-resort entry is the bare substring `observal_cli`. A user's own
`python3 ~/src/observal_cli/guard.py --deny ...` hook matched, was classified
as project-managed, and **was deleted** — patching a missing event could
silently disable a user's tool policy.

Fixed with the strict marker set at both sites (`a9bacf36`, 2 lines). Proved
with a small un-fixer that collapses the predicate back at exactly the two
sites and asserts the count is 2: **2 failed** pre-fix, **2 passed** after.
The doctor fixture also asserted the wrong module path and had never tested the
real command.

> An "is this ours?" check that gates a delete must match a specific module,
> script or endpoint — never a bare package name.

## 8. `git add -A` in the workspace root, again

The rule is in AGENTS.md and I walked into it anyway: `git add -A` in the
workspace root staged **249 files I did not touch** — 65 gitlink entries for
sibling repos, patch files, `.bundle` backups, `*.migrated` state stubs — and
pushed in the same command chain.

Recovered with `git reset --soft HEAD~1`, `git reset -q HEAD .`, staging the
one intended file, then
`git push --force-with-lease=main:37641a0c origin main` **pinned to the SHA
being replaced**. Verified after: remote file count `1`, gitlinks `13`.

Three rules, all previously written and all broken in one command:
stage by explicit path; **separate commit from push** so `--stat` gets read;
use `--force-with-lease=<ref>:<exact-sha>`, never a bare force.
