### Why every suite was green

The status codes were **always correct**. `assert resp.status == 204` passed in all four.
The defect lived between "I have a `Response`" and "bytes are on the wire", and three
different shims hid it:

1. a hand-rolled WSGI adapter (no socket — framing unobservable);
2. `http.client`, GET only (the transport was exercised, on the one path that was right);
3. calling the handler directly and asserting on the returned dict (no transport at all).

The general form is the prompt: **a test that constructs the response cannot validate it.**

### The four failure modes, by cost

1. **No `Content-Length` on keep-alive.** HTTP/1.0 frames by EOF, so curl and the suite
   agree it works; a proxy speaking 1.1 upstream either stalls waiting for a length or reads
   the next status line as body bytes and hands the app corrupt JSON intermittently.
2. **A body after 204/304.** Desynchronises unconditionally. HEAD is the expensive variant:
   headers right, payload written and discarded by every client that reads it.
3. **`int(self.headers["Content-Length"])` outside a `try`.** `Content-Length: abc` raises
   inside `handle_one_request`, which logs and sends **nothing** — the caller sees a timeout.
   On a webhook endpoint the retry queue for that endpoint never drains. A 400 costs a line.
4. **501 on HEAD.** Prometheus scrapes with GET, so the suite tested GET. Every uptime
   checker, sidecar and cloud LB sends HEAD: a reproducing endpoint that 501s reads as an
   unhealthy backend and leaves rotation.

### The invariant

```python
assert headers["content-length"] == str(len(body))
```

True of any correct server, false of one that omitted, miscounted, or wrote an undeclared
body. It is written in terms of the response rather than a constant, which is why it covers
the class instead of the instance.

### Found by one grep

```bash
grep -rln "send_header\|Content-Length" --include=*.py .
```

The fourth repo had byte-identical code because `_json_resp` was copied when it was created.
**Copy-paste is how a defect becomes a convention.** In the other direction, a deliberate
non-change: `tiny-router` still does not route HEAD to a GET handler (HEAD is registered
explicitly, so 404 is right), and a test now pins that so adding a fallback later is a
visible decision.

New: `prompts/a-test-that-constructs-the-response-cannot-validate-it.md`,
`tools/asserting-on-the-wire-not-the-object.md`.
