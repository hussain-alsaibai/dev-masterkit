# The CI Census - 25 Repositories, 8 Real Defects

**Measured 2026-10-28. Every count in this report was produced by running the
suite, not by reading a badge.**

## The question

> **Which repositories have a test suite that nothing has ever executed?**

Twenty-five tiny-* repositories had a test suite and **no workflow file at
all**. Adding one to each found **8 real defects**, including two libraries
whose central function could never run at all.

**Every one of the eight had shown a green local test run at some point.**

## Why a green local run proves nothing

```bash
pip install -e .     # editable install: the SOURCE TREE is on sys.path
pytest                # -> imports the loose .py file next to the test
```

An editable install puts the source directory on `sys.path`. A loose
`tiny_semantic_cache.py` next to `test_tiny_semantic_cache.py` is imported
**as if it were the installed package**. The suite exercises the working tree
- which is fine - but it never proves the **wheel** ships the module.

Five packages passed `pip install -e .` and still published a wheel with
**zero importable modules**.

## The check that matters

```bash
uv venv "$HOME/.venvs/probe" --python 3.11
VIRTUAL_ENV="$HOME/.venvs/probe" uv pip install -e . pytest

# import from OUTSIDE the source directory
cd /tmp && "$HOME/.venvs/probe/bin/python" -c "import tiny_semantic_cache; print('OK')"
```

**Step 2 is the one people skip.** From inside the repo the loose source file
shadows the installed package and the defect is invisible.

## The 8 defects, in full

### 1. tiny-semantic-cache - `cosine_similarity` raised on every call

```python
# BROKEN
norm_b = math.sqrt(sum(x * y for y in b))   # `x` is not in that generator

# CORRECT
norm_b = math.sqrt(sum(y * y for y in b))
```

The similarity function the whole package is built on. Every semantic lookup
was broken. **9 failed / 9 passed -> 20 passed.**

### 2. tiny-ai-workflow - the library could not create a single WorkflowStep

```python
# BROKEN - `default_factory` is a CALLABLE that dataclasses invokes
result: Any = field(default_factory=None, init=False)

# CORRECT
result: Any = field(default=None, init=False)
```

`None()` raised `TypeError: 'NoneType' object is not callable` on every step
registration. `@wf.step()` could never work. **3 passed / 9 failed -> 12
passed.**

### 3. tiny-file-watcher - renames reported as DELETED + CREATED

A rename is not atomic. Between the two halves of `os.rename` the old path is
gone and the new path does not exist yet. A scan landing in that window sees a
deletion; the next scan sees a creation. The detector compared inodes between
**consecutive** snapshots, so the pairing was lost permanently.

Reproduced at ~1 run in 30; the rename test failed **3 of the 6** CI matrix
jobs (3.8, 3.12, 3.13). The fix keeps an `inode -> last-seen-path` map.
**400-trial harness: 0 misses**, where the old code missed 2-4 per 60.

### 4. tiny-scheduler - `stop()` raised TypeError on Python 3.8

`ThreadPoolExecutor.shutdown(cancel_futures=...)` is **3.9+**; the package
claims `>=3.8`. **4 of 57 tests failed on 3.8.** Now **60/60**.

### 5. tiny-bucket-quota - shipped the WRONG module

```toml
py-modules = ["tiny_rate_window"]   # copied from a sibling repo
```

The installed finder mapped a module that does not exist in this repo.

### 6. tiny-llm-router - the build failed outright

`py_modules` (underscore) instead of `py-modules` (hyphen).

### 7. tiny-jsonpath - the build failed outright

`package-data` used the empty-string key `""`, which modern setuptools
rejects.

### 8. tiny-diff / tiny-eval - duplicate test basenames

Two files named `test_tiny_diff.py` (repo root and `tests/`). pytest refused
to collect the second, and the `tests/` copy was stale - it imported APIs
that no longer exist.

## The packaging class of its own

`tiny-semantic-cache`, `tiny-ai-workflow`, `tiny-event-bus` and `tiny-task`
all shipped wheels with **no importable module**:

```toml
# WRONG - finds nothing; a single module is not a package
[tool.setuptools.packages.find]
include = ["tiny_semantic_cache*"]

# RIGHT
[tool.setuptools]
py-modules = ["tiny_semantic_cache"]
```

## A collection error is not a test failure

`snapdb`'s PEP 669 profiler bug produced **11 collection errors**, not 11 test
failures. The module could not be imported, so **nothing ran at all**. The
suite was unrunnable on two of the five Python versions in CI.

| outcome | what actually happened |
|---|---|
| `11 errors` | nothing ran - the test module could not be imported |
| `11 failed` | 11 assertions ran and were wrong |

## Method notes

- **`uv` replaces docker** for testing a Python version that is not installed:
  `uv python install 3.13` + `uv run --python 3.13 ...`. Fast, leaves no image.
- **`/tmp` on this host is a 512 MB tmpfs, not the 16 GB disk.** Creating one
  venv per repo under `/tmp` filled it mid-run and produced spurious
  `No space left on device` failures that looked like build errors. Venvs go
  under `/home/node/.venvs/`.
- **A local `pip install -e .` is not enough** to prove a wheel ships the
  module. The check that matters: fresh venv -> install -> `import <module>`
  from a different cwd. Five packages passed the editable install and still
  shipped nothing importable.
- **CI simulation that matches GitHub exactly**: fresh venv,
  `pip install -e .`, run the exact test command from the workflow, on the
  oldest and newest matrix versions. Anything less misses real failures.

## The generalisation

> **A repo with tests and no CI is not "tested" - it is untested in the only
> sense that matters. And a green local run is evidence about the source tree,
> not about the package.**

Eight of the twenty-five were broken in ways that made the library unusable.
None of it was subtle. All of it was invisible because **nothing executed the
tests in the environment the package claims to support.**
